# ✈️ מעקב מחירי טיסות — מדריך התקנה (חינם, ~15 דקות)

המערכת בנויה משלושה חלקים, כולם בחינם:
- **בודק מחירים** (`tracker/check.py`) – רץ אוטומטית ב־GitHub Actions 3 פעמים ביום (06:15 / 12:15 / 18:15 שעון ישראל, ±שעה בחורף), ושולף מ־Google Flights את המחיר לכל תאריך יציאה בטווח.
- **התראות** – ntfy (פוש לטלפון), וגם טלגרם ו/או מייל אם תרצה.
- **אפליקציה לטלפון** (`docs/`) – אתר שמותקן על מסך הבית: גרף מחיר לכל תאריך, מגמה, קישורים ל־Google Flights / Skyscanner / Kayak, הוספה ועריכה של מעקבים.

---

## שלב 1 – להעלות ל־GitHub
1. פותחים חשבון חינמי ב־https://github.com
2. לוחצים **New repository**, קוראים לו למשל `flights`, ובוחרים **Public**. ריפו ציבורי נחוץ כדי ש־Pages ו־Actions יהיו חינמיים. המשמעות: רשימת היעדים והמחירים גלויה לכל מי שיודע את הכתובת. סיסמאות ומפתחות לא נחשפים, כי הם נשמרים כ־Secrets.
3. בדף הריפו לוחצים **uploading an existing file** וגוררים את **כל התוכן** של התיקייה המחולצת, כולל התיקיות `.github`, `docs` ו־`tracker`.
   > אם התיקייה `.github` לא נגררת (קורה לפעמים בדפדפן), יוצרים ידנית קובץ חדש בנתיב `.github/workflows/check-prices.yml` ומדביקים לתוכו את התוכן שלו.

## שלב 2 – התראות לטלפון (ntfy)
1. מתקינים את אפליקציית **ntfy** (App Store / Google Play).
2. באפליקציה לוחצים **+ Subscribe to topic** ובוחרים שם **ארוך ולא ניתן לניחוש**, למשל `flights-danny-8f3k2q`. כל מי שיודע את השם יכול לקרוא את ההתראות.
3. ב־GitHub נכנסים ל־**Settings → Secrets and variables → Actions → New repository secret**:
   - Name: `NTFY_TOPIC`
   - Value: השם שבחרת

## שלב 3 (לא חובה) – טלגרם ו/או מייל
**טלגרם**
1. בטלגרם פותחים את `@BotFather`, שולחים `/newbot` ומקבלים **token**.
2. שולחים הודעה כלשהי לבוט החדש.
3. פותחים בדפדפן `https://api.telegram.org/bot<TOKEN>/getUpdates` ומעתיקים את המספר שמופיע אחרי `"chat":{"id":`.
4. מוסיפים שני Secrets: `TELEGRAM_BOT_TOKEN` ו־`TELEGRAM_CHAT_ID`.

**מייל (Gmail)**
1. מפעילים אימות דו־שלבי בחשבון Google.
2. יוצרים **App password** בכתובת https://myaccount.google.com/apppasswords
3. מוסיפים Secrets:
   - `SMTP_USER` – כתובת ה־Gmail
   - `SMTP_PASS` – סיסמת האפליקציה (16 תווים)
   - `EMAIL_TO` – לא חובה, אם רוצים לשלוח לכתובת אחרת

## שלב 4 – להפעיל את האפליקציה
1. נכנסים ל־**Settings → Pages**. תחת Source בוחרים **Deploy from a branch**, ואז Branch: `main`, תיקייה: `/docs`, ולוחצים **Save**.
2. אחרי דקה-שתיים האפליקציה זמינה ב־`https://<שם-המשתמש>.github.io/flights/`
3. מוסיפים למסך הבית:
   - **אייפון** (Safari): לחצן השיתוף ← "הוסף למסך הבית"
   - **אנדרואיד** (Chrome): תפריט ⋮ ← "הוסף למסך הבית" / "התקן אפליקציה"

## שלב 5 – בדיקה ראשונה
1. בלשונית **Actions** בוחרים **Check flight prices** ← **Run workflow**.
2. מסמנים את `test_alert` ומריצים. אמורה להגיע לטלפון התראת בדיקה.
3. מריצים שוב, הפעם בלי הסימון. זו בדיקת מחירים אמיתית, והתוצאות יופיעו באפליקציה תוך כ־2–3 דקות.

## שלב 6 (מומלץ) – עריכת מעקבים מהטלפון
1. ב־GitHub נכנסים ל־**Settings (של החשבון) → Developer settings → Personal access tokens → Fine-grained tokens → Generate new token**.
2. בוחרים Repository access: **Only select repositories**, ומסמנים את הריפו `flights`.
3. ב־Permissions מגדירים **Contents: Read and write** ו־**Actions: Read and write**.
4. באפליקציה לוחצים ⚙︎ ומדביקים את המפתח. הוא נשמר רק במכשיר שלך.
5. מעכשיו אפשר להוסיף מעקב, לערוך אותו, להשהות אותו או למחוק אותו. כל שינוי מפעיל בדיקה מיד, והכפתור ⟳ מריץ בדיקה ידנית.

## סריקה "לכל מקום מתחת ל־X"
בנוסף למעקבים הרגילים, כל בדיקה סורקת כ־107 יעדים מתל אביב: אירופה, יוון וקפריסין, הבלקן, הקווקז, המזרח התיכון, וגם יעדים רחוקים. אם יש יעד עם טיסה הלוך־חזור מתחת לסף, תגיע התראה אחת שמרכזת את כל היעדים האלה.

- **הגדרת ברירת מחדל:** מתחת ל־**100$**, טיול של **7 ימים**, יציאה בכל תאריך ב־90 הימים הקרובים, בלי הגבלת עצירות.
- **עריכה:** באפליקציה, בכרטיס הכהה למעלה ← "שינוי". אפשר גם לערוך בקובץ `docs/watches.json`, תחת `explore`:

| שדה | משמעות |
|---|---|
| `max_price` + `currency` | הסף והמטבע (`USD` / `ILS` / `EUR`) |
| `trip_days` | משך הטיול. `0` = כיוון אחד |
| `window_days` | כמה ימים קדימה לחפש |
| `weekdays` | ימי יציאה. רשימה ריקה = כל יום |
| `max_stops` | `0` / `1` / `"ANY"` |
| `destinations` | רשימת יעדים משלך. רשימה ריקה = הרשימה המובנית |
| `exclude` | יעדים שלא מעניינים אותך |

- **מתי חוזרת התראה על אותו יעד:** רק אם המחיר ירד ב־5% ויותר, או אם היעד יצא מעל הסף וחזר מתחתיו. כך לא תקבל את אותה התראה 3 פעמים ביום.
- **משך הסריקה:** בערך 4 דקות. היא רצה בתוך הבדיקה הרגילה, והזמן נכנס בנוח במכסה החינמית של GitHub.

## כללי ההתראה
ההתראה נשלחת כש:
- המחיר הזול ביותר בטווח יורד **מתחת ליעד** שהגדרת (`target_price`), או
- המחיר יורד ב־**10% או יותר** מהבדיקה הקודמת (משנים ב־`drop_alert_pct`).

אם המחיר נשאר מתחת ליעד, לא תגיע התראה חוזרת בכל בדיקה. התראה נוספת תגיע רק אם המחיר ירד עוד.

## עריכה ידנית של מעקבים
עורכים את הקובץ `docs/watches.json`:

| שדה | משמעות |
|---|---|
| `origin` / `destination` | קוד שדה תעופה (TLV, ATH, FCO, BCN, PRG, LTN…) |
| `from` / `to` | טווח תאריכי היציאה (עד חצי שנה) |
| `trip_days` | משך הטיול בימים. הערך `0` = כיוון אחד |
| `weekdays` | ימי יציאה, למשל `["thursday"]`. רשימה ריקה = כל יום |
| `max_stops` | `0` = ישירה בלבד, `1` = עד עצירה אחת, `"ANY"` = כל טיסה |
| `target_price` | מחיר היעד בש״ח, למבוגר אחד, הלוך ושוב |

## חשוב לדעת
- **מקור הנתונים.** המחירים מגיעים מ־Google Flights דרך ספריית הקוד הפתוח `fli` (החבילה `flights`). זה לא API רשמי של גוגל, ולכן כשגוגל משנה משהו זה עלול להפסיק לעבוד זמנית.
  - באפליקציה יופיע "הבדיקה נכשלה".
  - התיקון בדרך כלל הוא עדכון גרסה ב־`tracker/requirements.txt`.
  - הגרסה נעולה כרגע ל־`flights==0.9.0`, שנבדקה ועבדה בספטמבר 2026.
- **המחיר הוא אינדיקציה.** המחיר הסופי, כולל כבודה, נקבע באתר ההזמנה.
- **מקור גיבוי (לא חובה).** אפשר להירשם בחינם ל־Travelpayouts ולהוסיף Secret בשם `TRAVELPAYOUTS_TOKEN`, כדי לקבל גם מחירי Aviasales להשוואה. אלה מחירים שמורים מ־48 השעות האחרונות.
- **השבתה אחרי חוסר פעילות.** GitHub משבית תזמונים בריפו ציבורי אחרי 60 יום בלי פעילות בריפו. אם הבדיקות מפסיקות, נכנסים ל־Actions ולוחצים **Enable workflow**.
- **הרצה במחשב.**
  ```
  pip install -r tracker/requirements.txt
  NTFY_TOPIC=... python tracker/check.py
  ```
